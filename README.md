## 1. General Overview

IUU fishing (**Illegal, Unreported and Unregulated**) is one of the primary threats to marine ecosystems. Fishing vessels periodically broadcast their positions via the **AIS** (Automatic Identification System), and these tracks can be analyzed to infer what a vessel is doing at any given moment.

The project follows two stages:

1. **AIS point-level classification:** A Machine Learning model determines whether, at a given point, the vessel is **Fishing** or **Sailing**.
2. **Vessel-level detection:** Based on the predictions, a set of rule-based heuristics and an anomaly detection algorithm (**Isolation Forest**) assign each vessel an IUU suspicion score.

Two classification models are built and compared: a **Neural Network (NN)** and a **Random Forest (RF)**.

---

## 2. Objectives

* Clean and prepare a large AIS dataset (over 1 million points).
* Engineer features that describe vessel behavior: speed, turns, acceleration, time of day, etc.
* Train and compare two Fishing/Sailing classification models.
* Combine the models with domain-based rules and anomaly detection to identify suspicious vessels.
* Explain the results: why a vessel was flagged as suspicious.

## 4. Data Used

### 4.1. AIS Points

* **File:** `LicentaIUU_clean.csv`
* **Region:** North Sea / Danish straits (longitude 5–15°, latitude 53–60°)
* Each row represents a vessel position at time `t`.
* **Target label (`label`):** `1` = Fishing, `0` = Sailing

Main columns used in the analysis:

| Column | Meaning |
| --- | --- |
| `id` | Vessel identifier |
| `t` | Timestamp of the record |
| `latitude`, `longitude` | Position |
| `euc_speed` | Speed calculated between two consecutive points |
| `bearing` | Course / heading (degrees) |
| `signed_turn` | Change in heading (signed) |
| `distance_gap` | Distance from the previous point |
| `time_gap` | Time elapsed since the previous point (seconds) |
| `distanceToShore` | Distance to shore |

### 4.2. Exclusive Economic Zones (EEZ)

* **Source:** World EEZ v12 dataset (`eez_v12.shp`)
* Zones belonging to countries in the region (Norway, Denmark, Sweden, United Kingdom, Netherlands, Germany, Belgium, France) are retained and clipped to the area of interest.
* Used to determine whether a point lies within a national zone or in international waters (**High Seas**).

### 4.3. Data Cleaning

| Step | Effect |
| --- | --- |
| Drop `Unnamed` columns | Removes leftover index columns from CSV export |
| Convert `t` to datetime, `label` to integer | Ensures proper data types |
| Remove duplicates | Eliminates repeated rows |
| Keep only points with `time_gap` less than or equal to 3600 s | Removes very long gaps between consecutive points |
| Keep vessels with at least 10 points | Removes vessels with too little data |

* **Result:** **1,026,257 points**, **123 vessels**.
* **Label distribution:** **775,499 Fishing** (approx. 75.6%) and **250,758 Sailing** (approx. 24.4%). The dataset is therefore imbalanced.

## 5. Step-by-Step Methodology

### 5.1. Exploratory Data Analysis (EDA)

Distributions of speed, `time_gap`, heading, and turns are compared across the two classes. The means show clear differences:

| Metric | Sailing (0) | Fishing (1) |
| --- | --- | --- |
| Mean speed (`euc_speed`) | 6.48 | 2.65 |
| Mean distance to shore | approx. 12,975 | approx. 26,745 |
| Mean heading change (`signed_turn`) | 0.016 | 0.187 |

**Interpretation:** Vessels that are fishing move slower, stay farther from shore, and change direction more frequently.

### 5.2. Feature Engineering

For each vessel (in chronological order), the following features are computed:

| Feature | Description |
| --- | --- |
| `speed_rolling_mean` / `speed_rolling_std` | Rolling mean and standard deviation of speed over the last 5 points |
| `speed_rolling_mean_20` / `speed_rolling_std_20` | Same, over the last 20 points |
| `turn_rolling_mean` / `turn_rolling_std` | Rolling mean and standard deviation of turns over the last 5 points |
| `acceleration` | Speed difference from the previous point |
| `bearing_change` | Absolute value of heading change |
| `hour`, `month` | Hour and month |
| `is_night` | `1` if the hour is between 22:00 and 06:59 |

Sliding windows capture behavioral context (an isolated point says little, whereas a sequence of slow points with frequent turns suggests fishing).

### 5.3. Train / Validation / Test Split

The split is performed **by vessel**, not by point: a vessel appears in only one set. This prevents **data leakage** between training and testing.

| Set | Share | Vessels | Points |
| --- | --- | --- | --- |
| Train | 70% | 86 | 733,565 |
| Validation | 15% | 18 | 88,894 |
| Test | 15% | 19 | 203,798 |

Features are standardized using `StandardScaler`, fitted **only** on the training set.

### 5.4. Model 1: Neural Network (NN)

* **Input:** 17 features.
* **Architecture:** A single `Dense(1)` layer with `sigmoid` activation (18 parameters)—effectively a logistic regression model implemented in Keras.
* **Optimizer / loss:** `Adam` / `binary_crossentropy`.
* **Class imbalance:** Handled with `class_weight='balanced'` (Sailing approx. 2.03; Fishing approx. 0.66).
* **Early stopping:** `EarlyStopping` on `val_loss` with a patience of 20 epochs and restoration of the best weights (best epoch: 40).
* **Batch size:** 1024.

### 5.5. Model 2: Random Forest (RF)

* **Input:** 13 features selected based on importance (excluding, for example, `signed_turn`, `acceleration`, `bearing_change`, and `month`).
* **Number of trees:** Chosen via the out-of-bag (`OOB`) error curve for 10–200 trees in steps of 10. The minimum occurred at 140 trees (`OOB error` approx. 0.0197).
* **Hyperparameters:** `min_samples_leaf=50`, `min_samples_split=200` (limits overfitting), `class_weight='balanced'`.

Top feature importances in RF:

| Feature | Importance |
| --- | --- |
| `speed_rolling_mean_20` | 0.301 |
| `speed_rolling_mean` | 0.259 |
| `distanceToShore` | 0.146 |
| `euc_speed` | 0.141 |

**Conclusion:** Speed (especially smoothed over rolling windows) and distance to shore are the most important indicators.

### 5.6. Geospatial Analysis

* The EEZ boundaries are loaded and joined spatially (`geopandas.sjoin`) with the AIS points and EEZ polygons.
* Each point receives its sovereign country (`SOVEREIGN1`) and an `in_eez` indicator.
* Points outside any EEZ are labeled **High Seas**.
* **Distribution:** Denmark 926,996 · Sweden 53,007 · Norway 37,472 · High Seas 8,782 points.
* A map (with an OpenStreetMap basemap via `contextily`) is generated showing Sailing and Fishing points.

### 5.7. Suspicious Vessel Detection

Point-level model predictions are aggregated into a vessel-level score. The same procedure is applied separately for the NN and RF models.

#### Manual Rules

| Rule | Condition | Threshold to Flag Vessel |
| --- | --- | --- |
| 1. Loitering (stationary / slow movement with frequent turns) | Predicted Fishing, `euc_speed` less than 0.787, `speed_rolling_mean` less than 1.0, `turn_rolling_std` greater than 37 | More than 500 points |
| 2. Night fishing | Share of Fishing points occurring at night | More than 55% |
| 3. Suspicious AIS gap (possible transponder shutoff) | `time_gap` greater than 1800 s | At least 2 occurrences |
| 4. Fishing in international waters (NN variant only) | Predicted Fishing, outside EEZ | More than 200 points |

#### Isolation Forest

For each vessel, an aggregate profile is computed (mean and std of speed, turn variability, max `time_gap`, fishing share, night share, mean distance to shore, mean acceleration). An `Isolation Forest` model (`contamination=0.1`) flags vessels with an atypical profile compared to the rest of the fleet (**13 vessels** in both variants).

#### Final Score

`scor_final = loitering + pescuit_noapte + ais_gap (+ high_seas, NN only) + isolation_forest`

| Score | Interpretation |
| --- | --- |
| `0` | Normal vessel |
| `1` | Suspicious vessel |
| `2` | Suspicious vessel (multiple signals) |
| `3+` | Highly suspicious vessel |

### 5.8. Explainability

* **Random Forest:** For vessels with a score greater than or equal to 3, the mean of features on points predicted as Fishing is compared against the global mean, both in absolute terms and as percentage deviation.
* **Isolation Forest:** For vessels with a score greater than or equal to 2 that are also anomalies, the z-score of each aggregate feature is displayed (red = above average, green = below average).

This makes it possible to justify a "suspicious vessel" result using concrete behavioral characteristics.

## 6. Results

### 6.1. Fishing/Sailing Classification (Test Set: 19 Vessels, 203,798 Points)

| Metric | Neural Network | Random Forest |
| --- | --- | --- |
| Accuracy | 0.86 | 0.89 |
| F1 Sailing | 0.70 | 0.76 |
| F1 Fishing | 0.91 | 0.93 |
| AUC | 0.868 | 0.894 |

Random Forest outperforms the Neural Network across all metrics, suggesting that relationships among the features are nonlinear and not fully captured by a single-layer linear model.

### 6.2. Vessel-Level IUU Scores (123 Vessels)

| Final Score | NN | RF |
| --- | --- | --- |
| `0` (normal) | 79 | 79 |
| `1` | 13 | 13 |
| `2` | 5 | 2 |
| `3+` | 2 | 2 |

Number of vessels flagged by each rule:

* **NN:** loitering 17, night fishing 17, AIS gap 7, international waters 5, Isolation Forest 13.
* **RF:** loitering 15, night fishing 20, AIS gap 7, Isolation Forest 13.

A notable finding is that both models identify the exact same number of **highly suspicious vessels (2)** and the exact same number of **normal vessels (79)**, indicating that the conclusions are relatively stable across models.

> **Note:** The score is a risk indicator, not proof of illegal activity. Flagged vessels require further investigation.

## 9. Limitations and Future Work

### Limitations

* Rule thresholds (e.g., 500 points for loitering, 55% night fishing) are chosen manually and depend on this dataset.
* The `label` column may contain noise/errors, which the models learn from.
* The dataset includes only 123 vessels, so vessel-level results carry substantial uncertainty.
* The NN model is very simple (a single layer), making it comparable to logistic regression.
* There is no ground-truth set of confirmed IUU vessels, so the final score cannot be quantitatively validated against confirmed cases.

### Future Work

* Deeper neural networks or sequential models (LSTM, GRU) that operate directly on trajectory sequences.
* Threshold optimization (e.g., via vessel-grouped cross-validation using `GroupKFold`).
* Expansion to additional regions and longer time spans.
* Validation against official IUU vessel lists.
* Integration of additional data sources (weather data, marine protected areas, seasonal closures/bans).
